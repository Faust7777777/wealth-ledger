# 2026-07-15 Movement 语义与投资成本算法加固

## 问题

旧服务除 `transfer` 外只校验 movement 字段形状，不校验类型语义。直接 API 可以把
`income` 写成 `out`、把 `expense` 写成 `in`，也能用账户不支持的币种或畸形买卖腿
创建草稿。旧买卖应用还把持仓腿 `amount` 同时当作数量和成本，无法正确表达“10 股花
100 元”。

## 当前算法

- 收入、分红、利息：一条现金 `in/source`。
- 支出、费用：一条现金 `out/source`。
- 余额校准：一条现金 `adjustment`，方向可进可出。
- 转账：两个不同账户、同币种同金额、`out/source` → `in/destination`。
- 买入：现金腿是总成本，持仓腿是数量；现金减少总成本，持仓数量增加，成本基础增加
  现金成本。
- 卖出：持仓数量减少，现金增加实际回款；剩余成本基础按出售数量比例减少，因此实际
  回款和结转成本的差额自然进入净资产。
- 贷款放款：负债账户 `out/source` → 非负债账户 `in/destination`。
- 贷款还款：非负债账户 `out/source` → 负债账户 `in/destination`。
- 普通 draft 不得直接声明 `correction`，必须走更正端点。
- 含持仓腿的投资记录暂不允许更正，避免把数量反向分录错误应用到成本基础；普通现金、
  转账等既有更正路径保持可用。
- 分录币种必须由账户支持；持仓腿只能进入 `holdings` / `mixed` 账户；同一 instrument
  的 quote currency 不得漂移。

报价后持仓市值为 `quantity × price`。只有市值与成本基础币种一致时才计算未实现盈亏；
缺少历史成交 FX 时不对不同币种裸数字做减法。

## 回归

新增 HTTP API 级覆盖：

- 反向 income/expense、错误 adjustment、账户不支持币种、直接 correction 均返回 400；
- 买入 10、总成本 100，卖出 4、回款 40后：剩余数量 6、成本基础 60、未报价净资产
  保持 1000；报价 12 后市值 72、未实现盈亏 12、净资产 1012；
- 贷款放款 500、还款 100 后：资产 400、负债 400、净资产 0；反向放款返回 400。

Rust 118 项测试、clippy、OpenAPI/contract check、mock/dev/Rust server smoke 与真实
local-ledger smoke 均通过。

## 明确边界

- 手续费、税费对投资成本基础的多腿归属尚未扩展，不能静默混入数量。
- 投资记录更正要先定义数量、成本基础和已实现盈亏的完整 replacement 算法；当前服务
  明确拒绝，而不是沿用普通金额更正。
- DCA 计划只知道计划投入金额，尚不知道真实成交数量；当前自动候选仍是待复核边界，
  后续应让用户在确认前录入成交数量/价格，不能把计划金额长期当成真实份额。
- 历史成交 FX 尚未进入 movement schema；成本和市值币种不同会省略未实现盈亏，而非
  使用当前汇率伪造历史成本。
