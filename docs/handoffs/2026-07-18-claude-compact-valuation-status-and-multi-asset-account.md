# Claude 前端续作：弱化估值状态与多资产账户

日期：2026-07-18  
基线：恢复工作时使用 `origin/feat/subscription-sync-integration` 最新提交。

## 1. 问题背景

用户真实首页在存在缺失汇率时显示了大面积“待处理”卡片，并在净资产下固定写：

```text
0 项报价过期 · 本地缓存
```

实际服务端状态是 `unpriceable`，不是 stale，也没有本地缓存。大卡片视觉权重过高，技术状态文案也误导用户。

用户同时明确提出：交易所账户（例如 OKX）需要在一个账户下保存 USDT、BTC、ETH 等多种资产，原始数量分别保留，再统一估值显示；不能把整个账户强制成一种单位。

## 2. P0：首页估值状态降级

- `quoteProblemCount` 不再进入首页的大型“待处理”卡片；该卡片只保留真正需要用户立即操作的 AI 待确认、账户异常、定投到期等项目。
- 净资产附近最多显示一个低强调的小状态入口，例如：

```text
估值待完善 3
```

- 不常驻显示“本地缓存”“报价过期”“unpriceable”等技术判断。
- 不因估值不完整把净资产金额变成强警告色。
- `≈` 可以保留，但应与小状态入口形成一个紧凑区域，不另占一整行大警告。
- 没有估值问题时入口完全隐藏。

## 3. P0：点击后的简短说明

点击小入口打开受限宽度的 dialog/bottom sheet：

- 标题：`部分资产暂未计入总值`；
- 简短说明：`缺少有效报价或汇率时，我们会保留原始数量，不会猜测价格。`；
- 按账户/资产列出原始数量，例如 `OKX · BTC 0.00076078`；
- 缺汇率时显示 `缺少 BTC → CNY 的估值路径`；
- stale/offline cached 才可以分别显示“报价较旧”或“使用缓存报价”；
- 提供“刷新估值”主操作和“关闭”；失败不关闭面板；
- 不显示内部 ID、wire enum、provider 实现、MVP 或后端说明。

前端在后端提供详细 valuation issue DTO 前，可以从 accounts、holdings、quotes、fx-rates 的现有读模型组合展示；不得凭 `staleCount` 猜测所有问题都是“报价过期”。

## 4. P1：多资产账户详情

账户是资产容器，不是单一币种余额。账户详情按两组展示：

```text
现金与稳定币
USDT  125.30

持仓
BTC   0.00076078   ≈ ¥…
ETH   0.42         暂未估值
```

- 原始数量为主信息，折算金额为次信息；
- 账户总值使用用户本位币，但必须带质量和 as-of；
- 缺报价的资产继续展示原始数量，不按 0 隐藏；
- 不把 BTC/ETH 数量塞入账户 `defaultCurrency`；
- 添加资产入口等待 Codex 提供“持仓导入/数量调整”接口，不伪造买入交易。

## 5. 验收场景

1. 纯 CNY 账户：首页无估值入口、无大待处理卡。
2. 两个 USD/USDT 余额无 CNY 汇率：首页仅一个紧凑入口，点击后列出两个账户。
3. stale FX：面板正确写“汇率较旧”，不得写成缺失。
4. offline cached：只有此状态才出现“使用缓存”。
5. OKX 同时有 USDT/BTC/ETH：三种原始数量均显示；缺 ETH 报价时 BTC/USDT 不受影响。
6. 360 和 1200 宽均无 overflow；明暗主题各提供视觉证据。

## 6. 边界

- 不改 `server-rs/**`、契约、部署和生产数据；
- 不在前端猜价格、汇率或跨资产换算路径；
- 推送独立前端分支，完成后交回 Codex 集成。
