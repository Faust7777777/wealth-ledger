## 用户要求

Finwealth 是资产统计应用，用户理解其用途。页面不得反复声明应用不会下单、不会扣款、不会退订、不会转账，或解释 proposal/后端/账本实现机制。不要把用户当成需要持续教育的对象。

## 删除原则

从所有可见页面、常驻 subtitle、提示卡、dialog 正文和空态中删除以下类型：

- `本应用不会……`
- `只生成……不代表……`
- `不下单 / 不扣款 / 不转账 / 不连券商 / 不连银行`
- `确认后才写入账本` 的重复说明
- `候选 → 复核 → 入账` 等内部流程说明
- `真实 API / 后端 / 本地账本 / MVP`
- 把产品边界写成常驻帮助文字

代码注释和工程契约可以保留，但不得渲染给用户。

## 可保留内容

- 按钮和状态名：`待确认`、`已入账`、`已取消`；
- 短暂结果反馈：`已加入待确认`、`已保存`、`已取消`；
- 真实字段校验：`下次扣费日不能早于开始日期`；
- 不可逆或高风险操作的确认问题：`确认归档？`；
- 会直接影响数据的明确后果，但不得解释内部实现。

判断标准：一句话如果删除后，用户仍然知道“现在是什么状态”和“下一步能做什么”，就删除。不要用帮助卡、说明段、副标题或括号补充产品边界。

- 对 `lib/features/**` 做全文复查，不能仅修本任务单列出的文件；
- 页面不得新增“了解更多”卡片来搬运这些防御性说明；真正需要帮助时使用低强调入口，且内容只解释字段或操作，不解释应用不会做什么；
